P-001 — Integrate a GitHub-based MCP server into OpenClaw
PROVEN process / PARKED outcome. The integration *mechanics* all worked; the

Work

  • Goal: Add a third-party MCP server from a GitHub repo as a usable tool for main.
  • Definition of done: Tool callable from the agent; auth completed; at least one real

end-to-end call verified; documented + reversible.

  • Recurring constraints to check first:
  • Headless gateway host — no display, no browser, no passwordless sudo.
  • Does the server need a GUI/browser? (Cloudflare/Turnstile-style anti-bot defeats headless.)
  • Where does it persist credentials/session? Is that a leak risk?
  • ToS: are we automating a logged-in account in a way the provider restricts?
  • Wiring path: openclaw mcp set <name> '<json>' then gateway restart.

Workforce

  • main — owner: architecture decision, wiring, synthesis.
  • risk-assessor — ToS / fragility / security tradeoff review.
  • ollama-project-manager — checkpoint sequencing.
  • code-reviewer — review wiring + any wrapper scripts.
  • security-hardener — verify no credential/session leak.
  • bug-hunter — standby for DOM/anti-bot breakage.
  • docs-writer — framework + pattern documentation.

Workbench

  • Wiring: openclaw mcp set / openclaw mcp show / gateway restart via gateway tool.
  • Runtime: Node v24 + npx <pkg>@latest (no clone/build for this repo).
  • Browser: Playwright Chromium (npx playwright install chromium).
  • Display workaround candidate: Xvfb virtual display (apt) — needs sudo once.
  • Fallbacks: run MCP on a machine with a real screen; or skip browser + use API/web_search.
  • Files: this framework doc; WORKING_MEMORY.md status block.

Challenges (run 1 — being recorded live)

  • Host is headless; repo design *requires* a visible browser → primary risk.
  • No passwordless sudo → dependency install needs Bobby in the loop.
  • DOM-dependent extraction → fragile to Perplexity UI changes.

Specialist findings (run 1)

  • risk-assessor → NO-GO on browser path. P1 risk = ToS violation (automating a logged-in

Pro account is a textbook violation → suspension/loss of Pro). P2 = DOM fragility + Turnstile

lockouts. P3 = third-party MCP driving a live authenticated session. Xvfb marginally *raises*

detection (missing GPU/WebGL fingerprints). Recommendation: use the official Perplexity API.

  • security-hardener → if we proceed, hard requirements: profile dir OUTSIDE workspace,

700/600, encrypted, gitignored; pin/vendor the npx package (supply-chain); egress-allowlist

to perplexity.ai only; expose search-only tool surface; treat all results as untrusted (no

result-driven follow-on tool calls); human-in-loop for any non-search action; rate-limit queries.

Decision (run 1)

  • Browser-automation path carries real account-ban + supply-chain risk. Presented Bobby a

fork: (A) official Perplexity API, (B) browser MCP on a real-screen machine, (C) browser MCP

here via Xvfb with all security-hardener guardrails.

  • Bobby chose C (2026-06-01). Accepts the ToS/ban risk for the novelty; wants it done with

the full hardening checklist applied.

Standing rule: sudo audit discipline

  • Bobby granted passwordless sudo. Every sudo invocation MUST be logged to

~/.openclaw/audit/sudo-usage.jsonl (JSONL: ts, command, reason, outcome, session). Owner-only 600.

  • Pattern: pair each sudo command with an append to that log in the SAME action so it can't drift.
  • I do not self-create the sudoers grant; Bobby runs the grant command himself (don't self-modify safeguards).

Outcome (run 1) — PARKED 2026-06-01

  • Built the FULL stack successfully: Xvfb virtual display, headful Playwright Chromium (proven loading

example.com), pinned perplexity-web-mcp@1.1.1, locked profile dir (700), x11vnc over Tailscale for

remote login. All mechanics worked.

  • Blocker (as predicted): every load of perplexity.ai hit Cloudflare "Just a moment..." Turnstile

and would not clear. Root cause = the browser environment fingerprint (Playwright "Chrome for Testing"

build + Xvfb virtual display, no GPU), NOT the login method. Stealth flags (disable-AutomationControlled,

hide navigator.webdriver, ignore --enable-automation) did NOT get past it. Apple/Google OAuth popups were

even more hostile.

  • Bobby paused the task. Runtime services torn down (x11vnc, Xvfb, vnc passwd removed). Installed bits

(xvfb, x11vnc, chromium, pinned MCP, profile dir) left in place for a possible real-screen retry.

What worked / what to reuse

  • Parallel risk-assessor + security-hardener at task start — reshaped the plan in <1 turn, called the

blocker before any install. Highest-ROI move. ALWAYS do this for third-party integrations.

  • Pinned install (npm install pkg@version to a fixed path) instead of live npx — supply-chain safe.
  • Profile dir outside workspace, 700, symlinked into the package so it's upgrade-safe.
  • sudo audit discipline: every sudo paired with a JSONL append in the same action — worked cleanly.
  • x11vnc bound to Tailscale IP only = private remote GUI without public exposure. Good reusable pattern.

Challenges / gotchas to avoid next time

  • pkill -f <script> self-kills the exec shell (pattern matches the parent bash). Kill by explicit PID

instead, or use a very specific pattern. Cost me 3+ aborted turns.

  • Heredoc-written /tmp/*.cjs inside a backgrounded exec didn't always land. Use the Write tool to

create runtime helper scripts at a stable path — reliable.

  • require("playwright-core") doesn't expose .chromium (it's the registry object); use require("playwright").
  • Telegram→terminal paste corrupted long commands with slashes (the /etc/sudoers.d saga). For anything the

user must paste, prefer short tokens / cd first / an editor (visudo -f) over long one-liners.

  • A masked secret token (my ***) got typed LITERALLY by the user into a sudoers file. Never show a real

keyword as ***; spell critical literals out or have me write the file.

Leaner pattern to try next time

  • For "use my <SaaS> subscription as a tool": check for an official API FIRST. Browser-automation MCPs

against Cloudflare-protected sites are a near-dead-end on a headless box — confirmed empirically here.

  • If a browser MCP is truly required, run it on a real-screen machine the user owns (Path B), not Xvfb.
  • Decision rule learned: *headless host + Cloudflare-Turnstile-protected target = recommend API/Path B, do

not sink time into Xvfb stealth.*

P-002 — Zero-token voice-capture + local-transcription pipeline (Design A)
PROVEN. Built first as `goals/` (2026-06-02), then cloned as `daily/` (2026-06-03) — a second clean delivery proves the pattern.

Work

  • Goal: Capture Bobby's voice notes into a dedicated Telegram group and make them searchable/analysable with zero LLM tokens until an explicit analyse step.
  • Definition of done: Silent capture → local transcription → SQLite store → retrieval works with no agent turn; only analyse spends tokens. Survives reboot, set-and-forget.
  • Recurring constraints to check first:
  • OpenClaw's own tools.media.audio defaults to cloud STT + injects to the agent (paid + chatty). Must be bypassed.
  • Retrieval/capture/transcribe must NEVER be an LLM call (an LLM-routed "paste transcript" timed out — the original lesson).
  • Capture bot must be a separate bot, admin in the group (privacy mode) to read voice notes — not the main OpenClaw bot.

Workforce

  • main — solo build. No specialist bench needed; this is deterministic plumbing, not judgement work.

Workbench

  • Capture: dedicated Telegram bot (e.g. @GoalsCapture_bot / @DailySet_bot), token in .secrets/ (chmod 600); getUpdates poll → insert rows filtered to the one goal chat_id.
  • Transcription: faster-whisper 1.2.1 (model small, CPU int8) in goals/.venv; download file_id from Telegram, transcribe, store text, delete temp .ogg (Telegram itself is the free unlimited audio archive).
  • Store: SQLite *.db = source of truth; show.py is pure SQLite retrieval (no LLM).
  • Scheduling: user systemd timers (capture 10min, transcribe-idle 30min, transcribe-nightly 03:00) — true zero-token via local-scheduler/run-task.sh.
  • Web: systemd --user unit, python3 -m http.server, Tailscale-only (ports 8099/8100), change-detection publish.
  • LLM step: only analyse week / analyse vision / analyse day — one-shot synthesis over a SQLite-gathered bundle.

What worked / what to reuse

  • Design A (separate capture bot bypassing the media→LLM pipeline) is the core reusable idea: the messaging platform is free storage; capture/transcribe/retrieve stay deterministic; the LLM only touches a deliberate analyse.
  • Cloning goals/ → daily/ took one session and reused the same venv — strong sign the pattern generalises to any "voice → structured log" need.

Challenges / gotchas to avoid next time

  • Bot must be admin in the group or privacy mode hides voice notes; chat_id auto-discovers on first captured note.
  • Idle-gated transcription (--check-idle on load/core) avoids competing with foreground work.

Leaner pattern to try next time

  • For any "capture X cheaply, structure later": capture raw + deterministic first, add LLM analysis only as an explicit command. Never put the LLM on the capture/retrieve hot path.

P-003 — Free-LLM tracking + multi-provider/multi-key rotation
PROVEN. Catalog + rotation live; resilience hardened 2026-06-11 (cross-model fallback + full-pool usage).

Work

  • Goal: Keep tabs on free LLMs/APIs and actually *use* them — wire free models into fallbacks and run subagents on free tokens, surviving rate limits.
  • Definition of done: Daily catalog scan (zero LLM); deterministic command to print exact fallback wiring; a free-model subagent launcher that rotates models + keys and learns from real outcomes.
  • Recurring constraints to check first:
  • OpenClaw already has the discovery mechanism: openclaw models scan (OpenRouter :free catalog) + openclaw models status (native usage/quota). Wrap built-ins; don't reinvent.
  • :free models need an API key to RUN even though catalog metadata is public.
  • Free tiers are per-day request-capped, so spread load and cool failures.

Workforce

  • main — solo build, iterative hardening.

Workbench

  • free_llm.py (SQLite free_llm.db): scan/list/best/wire/diff/providers/status/pick/agent/reliability/keys.
  • providers.json curated registry; fetchers.py pulls per-provider /v1/models (OpenRouter, Cerebras, NVIDIA, Groq, Mistral, Puter) using keys from auth-profiles.json (not shell env).
  • Native multi-profile auth: keys = auth profiles <provider>:<name>; rotation via auth.order.<provider> + auth.cooldowns.
  • Reliability-weighted rotation: model_runs / key_runs track attempts/successes/cooldown; outcome classifier maps exit code + output → success/rate_limit/timeout/error.
  • Local systemd timer: daily 09:00 scan, zero tokens.

What worked / what to reuse

  • Wrapping openclaw models scan instead of building a crawler — public metadata, zero cost.
  • Recording the REAL outcome (not just launcher exit code) — catches exit-0 idle timeouts and 429s; cooldowns then route around bad models/keys.
  • Per-key validation flow (printf > .key in a plain terminal, live /v1/models + real completion check, then write into auth-profiles, shred temp) — added 5 providers safely.

Challenges / gotchas to avoid next time

  • Cerebras edge 403s default Python-urllib UA → set User-Agent: curl/8.0.
  • NVIDIA/Cerebras /models don't return context_length.
  • (Fixed 2026-06-11) cmd_agent originally retried only across keys, not models, and the active pool was capped at top-10 (--pool) / top-5 (wire -n). Hardened to fall through models and use the full eligible pool.

Leaner pattern to try next time
